# FinBot 安全 RAG 助手 Final Report 初稿

## 1. 项目概述

本项目实现一个面向课程/考试资料的安全 RAG 问答助手。系统支持账号密码登录、受限文档问答、资料归档、文档加密存储、完整性验证、Prompt Injection 防护、PII 防护和审计日志。

## 2. 成员 A：安全底座

成员 A 提供认证、文档加密、签名、哈希和审计能力：

- JWT 登录与用户身份管理。
- AES-256-GCM 加密存储上传文档。
- SHA-256 记录原文哈希，用于完整性校验。
- RSA 数字签名验证文档可信度。
- 审计日志记录登录、上传、下载、验证、拒绝访问和安全事件。

## 3. 成员 B：RAG / RBAC / AI 安全

成员 B 在问答链路中实现：

- 语义路由：将问题路由到教学资料、工程资料、隐私资料和公开资料等授权范围。
- 检索层 RBAC：不同 chat role 只能访问授权 collection。
- 输入防护：Prompt Injection、PII、离题和有害意图拦截。
- 输出防护：来源引用、grounding 校验和跨部门泄露提示。
- 审计写入：正常 query 与阻断 query 均写入日志。

## 4. 成员 C：前端展示、测试与答辩材料

成员 C 将 A/B 的能力整合成可演示系统：

- Next.js 助手界面：登录、问答、角色化资料归档、不同权限可见范围。
- Demo 账号：Admin、Teacher、TA、Student，必须用对应账号密码登录。
- 测试用例：正常问答、越权访问、Prompt Injection、PII、篡改检测。
- 审计指标：攻击次数、敏感查询次数、未授权访问次数、篡改检测次数可由后端接口统计。
- 答辩材料：测试用例表、Demo 脚本、截图目录、PPT 主稿。

## 5. 核心安全流程

用户问题进入 `/api/chat` 后，系统执行：

1. 输入防护检测 Prompt Injection 和 PII。
2. 语义路由判断目标文档库。
3. RBAC 校验当前角色是否有权访问目标 collection。
4. RAG 检索授权文档片段。
5. LLM 基于上下文生成答案。
6. 输出 guardrails 和来源引用。
7. 记录审计事件并更新 Risk Dashboard。

| 篡改检测 | 通过 | 非破坏性模拟记录 tampering 事件 |

## 8. 总结

FinBot 不只是一个 RAG demo，而是一个带认证、加密、签名、权限控制、输入输出安全和风险审计的完整安全资料助手。成员 C 的工作让系统能够被老师稳定演示、复现测试，并用截图和材料证明每个安全能力。
